# 02: TUI shell: provider popup, input and a streaming transcript

**What to build:** `make run` opens the ratatui TUI.

1. A modal popup asks the user to choose DeepSeek or Qwen, preselecting the last choice stored in settings. If `WORKSPACE` is unset, it also asks for a workspace path. If `AI_API_KEY` is unset, it shows a blocking error.
2. The user types or pastes a multi-line message (Enter sends, Alt+Enter adds a newline, bracketed paste works) and watches the reply stream into the transcript as markdown.
3. A status line shows a spinner while the turn runs.
4. Ctrl+C cancels a running turn; a second Ctrl+C quits and restores the terminal. `/quit` also exits.

Use the dark theme with the banana-yellow accent from the start, in one theme module. Rendering is throttled to about 30 fps, and deltas append without re-rendering the whole transcript.

## Notes

For tickets 03, 08, 09, 13 and later.

**Crate layout** (`rust/crates/harness-tui/src/`):
- `theme.rs`: the one dark palette + banana-yellow accent (`ACCENT = #FFE135`), as `ratatui::style::Color` constants (`BACKGROUND`, `TEXT`, `MUTED`, `BORDER`, `ACCENT`, `ERROR`) and `Style`-returning helpers (`base`, `border`, `border_focused`, `accent`, `accent_bold`, `muted`, `error`). Colours are truecolor `Rgb`; there's no separate 256-colour table — terminals without truecolor degrade these on their own. Ticket 13 should keep adding to this module rather than hand-rolling styles elsewhere.
- `app.rs`: pure state, no ratatui/crossterm/terminal I/O. `App { screen: Screen }`, `Screen::Startup(StartupState) | Screen::Main(MainState)`. Constructors: `App::new_startup(selected: Provider, needs_workspace: bool, key_missing: bool)`, `App::new_main(provider, workspace: PathBuf)` (used directly by tests and by the real flow via `App::enter_main`). Accessors `startup_mut()`/`main_mut()` return `Option<&mut _>` for the active screen.
  - `StartupState`: `selected: Provider`, `needs_workspace: bool`, `workspace_input: String`, `key_missing: bool`, `workspace_error: Option<String>`. `toggle_provider()` flips the two-way choice; `ready() -> Option<(Provider, String)>` is `None` while the key is missing or a required workspace field is empty.
  - `MainState`: `provider`, `workspace: PathBuf`, `transcript: Vec<TranscriptItem>`, `input: String`, `turn_running: bool`, `spinner_frame: usize`, `quit_armed: bool`, `last_error: Option<String>`. `push_user_message(text)` appends a `TranscriptItem::User` and sets `turn_running = true`. `apply_event(harness_core::Event)` is the seam: it switches on `EventKind` (`TurnCreated` is a no-op here; `ModelMessage{message: None}` opens a new `TranscriptItem::Assistant`; `ModelMessageDelta` appends to that message's `content` by `(thread_id, message_id)`; the final `ModelMessage{message: Some(_)}` replaces `content` with the assembled text; `TurnDone` clears `turn_running`/`spinner_frame` and records `last_error` on `TurnState::Error`). `tick_spinner()` is called by the run loop's throttle tick, not by `apply_event`, so tests don't need to fake animation frames.
  - No tool-card/subagent/compaction variants exist yet because `harness_core::EventKind` doesn't have them; when 03/08/09 add tool and thread events, extend `apply_event`'s match rather than adding a parallel path.
- `ui.rs`: `pub fn draw(frame: &mut Frame, app: &App)`, pure (never mutates `app`). Delegates to `draw_startup`/`draw_main`; the popup uses a `centered_rect` helper. The selected provider line is prefixed `"> "`, the other `"  "` — tests assert on that prefix in the rendered buffer text (`terminal.backend().to_string()`), not on styles or private state.
- `lib.rs`: `pub async fn run() -> Result<()>` owns the terminal (a `TerminalGuard` that enters raw mode + the alternate screen + bracketed paste, and restores all three in `Drop`, so the terminal is restored even on an error return or a panic-free early exit) and the `tokio::select!` loop over: a ~33ms redraw tick (only redraws when `dirty`), the running turn's event channel (via `recv_turn_event`, pending forever when there's no turn), and crossterm's `EventStream`. Key interpretation is a pure function `interpret_key(&mut App, KeyEvent) -> Action`, kept separate from the I/O side effects (opening the harness, starting a turn) that `run()` performs in response to the returned `Action`. Not covered by tests (needs a real terminal); exercised by code inspection plus the smoke check above.

**Settings persistence (reconcile with 08):** added `harness-store` migration `0002.sql`: a single `setting(key TEXT PRIMARY KEY, value TEXT NOT NULL)` table, matching the spec's persistence table (§6) exactly, so 08 should build on this table (e.g. add more keys) rather than redefine it. `Store::get_setting(key) -> Result<Option<String>>` / `Store::set_setting(key, value) -> Result<()>` (upsert). The TUI reads `"last_provider"` before showing the popup (falls back to `Provider::DeepSeek` if unset or unparsable) and writes it once the popup is confirmed, before `Harness::open` (which takes ownership of the same `Store`).

**Cancel (`harness-core`):** `TurnState` gained `Cancelled` (`as_str()` → `"cancelled"`; the headless `run` subcommand now maps it to exit code 2, matching the spec's §9 exit-code table). `TurnHandle` gained a private `cancel: CancellationToken` field and `pub fn cancel(&self)`. `TurnRunner::execute` now returns `Result<TurnState>` instead of `Result<()>`; it `tokio::select!`s (in `biased` mode, so a cancellation always wins over an already-buffered event) between `self.cancel.cancelled()` and both the initial `client.stream(&messages)` call and each `stream.next()` in the delta loop, returning `Ok(TurnState::Cancelled)` immediately when the token fires. No required-action plumbing exists yet (05's job); with no tool calls in this ticket's scope, cancel only needs to interrupt the streaming HTTP call, which it does. The fake-provider test helper (`harness-core/tests/common/mod.rs`) gained `FakeProvider::push_sse_slow(body, chunk_delay)`, which sleeps `chunk_delay` before writing each SSE part, so `tests/cancel.rs` can deterministically cancel mid-stream (waits for the `model.message` start marker, then cancels, ran 10x locally with no flakes).

**Keybindings implemented now:** Startup: ↑/↓ toggle provider, characters/backspace edit the workspace field when needed, Enter confirms (validated by `StartupState::ready`), `q`/Ctrl+C quit (works even on the blocking `AI_API_KEY`-missing screen). Main: Enter sends (no-op while a turn is running or input is blank), Alt+Enter inserts `\n`, Backspace/characters edit `input`, bracketed paste (`crossterm::event::Event::Paste`) appends the pasted text to `input` (or to the workspace field pre-confirmation), Ctrl+C cancels a running turn or arms a "press again to quit" state (any other key disarms it), `/quit` (typed then Enter) exits. Not yet implemented (13's scope per the spec): PgUp/PgDn scrolling, Ctrl+B sidebar toggle, Ctrl+E `$EDITOR`, `/new` `/sessions` `/provider` `/undo` `/help`.

**Deviations / simplifications:**
- Workspace-path validation on `Enter` from the popup only handles the common failure (a path that doesn't `canonicalize()`) by staying on the popup with an inline `workspace_error`. A failure in `Harness::open`/`Config::embedded_default`/`api_key_from_env` after that point is treated as fatal (propagated out of `run()` as an `Err`, printed to stderr after the terminal is restored) rather than returned to the popup, because those should not fail in practice (the config is embedded and the key's presence was already checked) — recovering the `Store` from inside a partially-consumed `HarnessOptions` on that rare path isn't worth the complexity.
- No manual `ratatui-textarea` widget: multi-line input is a plain `String` with `\n`s inserted on Alt+Enter/paste, rendered via `Paragraph`'s automatic line-splitting. `ratatui-textarea` stays pinned in `[workspace.dependencies]` but unused; pull it in later only if the plain-`String` approach turns out to need real cursor/selection editing.
- No PgUp/PgDn scroll offset on the transcript yet (out of this ticket's acceptance criteria; spec §8 lists it, ticket 13 owns transcript/input detail).
