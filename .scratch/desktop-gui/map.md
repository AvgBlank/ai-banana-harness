## Decisions so far

- [Scope, stack and constraints for the desktop app](issues/00-scope-and-stack-decisions.md): build-ready spec; v1 is icon rail, workspace/session sidebar, home composer, conversation with tool cards, Changes panel, approvals, model picker; dark-first banana theme plus cream light; macOS first; Electron + React + TS + Vite + Tailwind + shadcn; Rust sidecar over NDJSON stdio; ADR 0003; one lazy `Harness` per workspace; "session" wording; three test layers in `make lint`/`make test` and CI.

- [Which GUI operations the core already supports](issues/01-core-gap-inventory.md): sending turns, streaming events, cancel, approval reply and undo exist; transcript replay, real diffs, rename and serde on `Answer`/`UndoOutcome`/`Provider`/`Session` are missing. Each provider has one fixed model, and one `Harness` per workspace is confirmed.
- [Compatible toolchain and versions](issues/02-toolchain-versions.md): Node 24, pnpm, electron-vite + electron-builder, Tailwind 4 with shadcn 4, Monaco bundled locally, Playwright `_electron`; some compatibility items still unverified.
- [Core API additions the GUI needs](issues/10-core-api-additions.md): serde on `Answer`/`UndoOutcome`/`Provider` (core) and `Session` (store), `Harness::transcript` for replay, `workspace_changes` moved into core with real patches plus `turn_changes`, one overwriting `set_session_title` with `rename_session`, `providers()` for a one-model-per-provider picker, `last_provider` helper, one `Store` handle per `Harness`. No change to `Harness::open`.
- [Sidecar crate placement and wire protocol](issues/03-sidecar-placement-and-protocol.md): new `harness-bridge` library crate (depends on core only) behind `banana-harness serve --stdio`; protocol v1 is NDJSON with `ready`/`request`/`response`/`event`/`fatal` frames and string ids; 16 methods (sessions, workspaces, turns, `action.reply`, undo, providers, two change scopes); events wrapped with workspace, session and turn ids; one running turn per workspace; no fs/shell methods; workspace config loaded only when trusted; key only via the sidecar's environment; no test hook, the fake provider is reached through `base_url` config.
- [Electron main/preload design and security](issues/06-electron-process-and-security.md): main owns a `SidecarSupervisor` (10 s ready handshake, zod-validated frames, 3 restarts per 60 s then a Restart button, `shutdown` then SIGTERM/SIGKILL, single instance); the key comes from `AI_API_KEY` env, then a login-shell probe (which also fixes `PATH`), then a memory-only session entry, never persisted; workspaces always open restricted first and upgrade only after a content-hash-bound trust decision (`trust.json`, MCP/permission/`base_url` summary, post-open provider-host check); sandboxed, context-isolated renderer on a custom `app://` origin with a strict CSP, an allowlisted `window.banana` API and confirmed `https:` links; main buffers the live turn, Rust stays durable truth and the renderer reduces events deduped by `event.id`; preferences and trust live in separate `userData` files.
- [Banana design system and screens](issues/04-banana-design-system.md): the user approved the prototype on 2026-10-17 and the tokens in `prototype/src/styles/tokens.css` are frozen (dark `#1a1914` + `#ffd60a`, banana-cream light, restrained diff tints); only five accessibility values changed (`--text-faint`, `--peel`, light `--focus`); `pnpm tokens:check` guards parity and contrast; the prototype stays as the visual reference; decisions kept: no Keychain, "session" wording, the approved Electron/Rust architecture.
- [Renderer state model and Changes panel data](issues/07-renderer-state-and-changes-panel.md): a pure `reduceTurn` in the renderer deduping by ULID `event.id` and treating the final `model.message` as authoritative (the start marker and deltas are never persisted); resume then `live.attach` with main retaining the last turn's buffer; running turns become interrupted on sidecar loss; subagent threads nest inside their `create_sub_agent` card by title; approvals queue; summary cards derive from diffs while the Changes panel (Last turn and Workspace scopes, stale-while-revalidate, single-flight refresh) is the authoritative tree view; lightweight diff view, no Monaco in v1; Undo only for the last finished turn with a checkpoint, behind a confirmation, and recorded by a new durable `turn.undone` event.
- [Running the sidecar against the fake provider](issues/05-fake-provider-for-smoke-tests.md): verified with the real binary that a stub reached only through `base_url` in layered config, plus `XDG_CONFIG_HOME`/`XDG_DATA_HOME` and an empty environment, is a complete test seam (Bearer key, streamed events, isolated database, real user dirs untouched); `NO_PROXY=127.0.0.1,localhost` is required (a proxy variable breaks the existing offline suite today); proposed: one dev-only `harness-testkit` crate owns the stub (gates, failure replies, watchdog, control API), fixtures and `TestEnv`, a `fake-provider serve` binary that exits on stdin EOF, and shared scenario JSON files run by the in-process bridge tests, the real `serve --stdio` process test and Playwright; provider `host` becomes URL authority plus `scheme`.
- [Repo layout, Makefile, CI and packaging](issues/08-repo-layout-make-ci-packaging.md): `gui/` is a standalone pnpm project beside the Rust workspace, with new `harness-bridge` and a dev-only `harness-testkit` crate (`default-members` keeps `make setup` lean) and the frozen prototype left in `.scratch/desktop-gui/prototype/`; Node 24 and pnpm 10.29.2 with exact pins, `--frozen-lockfile` and `engine-strict`; Biome replaces ESLint (typescript-eslint cannot use TypeScript 7); all dependencies are dev dependencies so the package has no `node_modules`; `gui-*` Makefile targets keep the Rust-only path Node-free, and `make test` carries the verified `NO_PROXY` expression; CI adds a Linux and macOS `gui` job (e2e under `xvfb-run`, key-leak grep before artifact upload) and a macOS `package` job; unsigned arm64 DMG and ZIP with the sidecar at `Contents/Resources/bin/banana-harness`; Windows and Linux packages out of v1. Verified by smoke builds: unsigned packaging, bundled sidecar, packaged-app launch under Playwright, bundling of dev dependencies.
- [ADR 0003 and CONTEXT.md wording](issues/09-adr-and-vocabulary.md): ADR 0003 "Desktop app as a third surface, over a Rust sidecar" drafted (ADR 0001 gets one appended "Update" paragraph, ADR 0002 untouched; the GUI toolchain stays in `gui/AGENTS.md`, not the ADR); `CONTEXT.md` adds *desktop app*, *sidecar*, *interrupted turn*, *undone turn*, *workspace config*, *restricted mode*, *workspace trust* and *changes* and drops the "avoid GUI" line, with no term for the test-support crate; `AGENTS.md` gains the crate boundaries, four test seams, no-test-hooks, workspace-trust and stdout rules; `gui/AGENTS.md`, README and CONTRIBUTING edits drafted. All text is in `drafts/`, checked by diff and script; nothing applied yet.
- [Slice the build into implementation tickets](issues/11-implementation-slicing.md): [spec.md](spec.md) holds the milestones M0 to M7, the test seams, the rules every ticket follows and the staged documentation plan; [build/](build/) holds 27 dependency-ordered tickets (docs, Rust core, test kit, bridge, GUI as vertical slices with a tracer bullet at 18, CI at 19, packaging, final acceptance), each with scope, files, acceptance criteria and verification commands; checked by script for order, links and completeness; nothing built or applied.

## Not yet specified

- Settings screen contents beyond theme and model.
- Keyboard shortcuts and command palette parity with the TUI slash commands.
- Signing, notarization and auto-update (the unsigned build comes first); universal or Intel macOS builds; Linux packages; the app icon asset (`build/icon.icns` from the approved banana mark).
- MCP OAuth prompt and MCP status presentation in the GUI (needs serde on `McpServerStatus` and likely an `mcp.status` method).
- Hardening `{env:VAR}` expansion in MCP `env` so it can never hand `AI_API_KEY` to a server (a core change outside this effort unless you want it in).
- Context-usage bar and token counters (the TUI has them; the protocol has no compaction-threshold method and the prototype has no such element).
- A core change so undo tells the agent (a context note); v1 shows a composer hint only.
- Interrupted-turn cleanup (turns left `running` after a crash) and a slow-consumer timeout for the sidecar.

## Out of scope

- Voice input and microphone controls, and marketing or update badges (decided out for v1).
- Windows packaging and an HTTP/WebSocket API or native Node bindings.
