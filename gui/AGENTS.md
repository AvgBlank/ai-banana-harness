- This file adds rules for the desktop app in `gui/`; the root `AGENTS.md` applies as well (vocabulary, one owner per definition, no unused code, comment style, secrets).
- Toolchain: Node 24 (`.node-version`, `engines`, `engine-strict`), pnpm pinned by `packageManager`, TypeScript 7 in strict mode. Install only with `pnpm install --frozen-lockfile`; versions are exact; every dependency is a `devDependency` because the main, preload and renderer bundles contain them and the packaged app ships no `node_modules`. A package that must stay external (a native module) is recorded here as an exception first.
- TypeScript 7 rejects `baseUrl`: use `"paths": { "@/*": ["./src/*"] }`. Components are written by hand in shadcn's style; the shadcn CLI is not part of the toolchain.
- Biome is the one linter and formatter (`typescript-eslint` does not support TypeScript 7). `make gui-lint` MUST be clean, including its accessibility rules: every `<button>` has a `type`, interactive elements are semantic.
- Process boundaries: the Electron main process owns the sidecar, the file system, dialogs, workspace trust, preferences and the API key; the preload exposes one frozen, allowlisted `window.banana`; the renderer is views plus a pure reducer in `src/renderer/state` with no Electron or Node imports; `src/shared` holds the schemas that validate every sidecar frame and every renderer call.
- Security: context isolation and the sandbox stay on and Node integration stays off; the renderer loads from the custom origin under the strict content security policy; permission requests and navigation are denied; external links open only as `https:` after a confirmation. The renderer MUST NOT supply trust decisions or paths main does not already know. The key lives in main's memory and the sidecar's environment only, and nothing logs request params, results or event payloads.
- Workspaces open in restricted mode first and load `.banana-harness/config.toml` only after the user trusts that exact file. After a trusted open, main blocks any provider whose URL authority (host and port) or scheme differs from the baseline without the user's approval, and any non-HTTPS endpoint that is not loopback.
- Design: the tokens in `src/renderer/styles/tokens.css` are frozen, and `make gui-lint` runs `check-tokens`. Layout, spacing, type and component structure follow the approved prototype in `.scratch/desktop-gui/prototype/`; a visual change needs a concrete bug or an accessibility failure. Every component MUST work in the dark, light and system themes.
- Words: the interface says "session", "workspace" and "turn", never "chat" or "thread".
- State: the reducer is pure, deduplicates by `event.id`, treats the final `model.message` as authoritative, and reads no clock (durations come from event id timestamps). Interrupted and undone turns are derived, not stored by the app.
- Tests live in `gui/tests/unit` (Vitest: the reducer and main-process modules under Node, components under jsdom) and `gui/tests/e2e` (Playwright against a real sidecar). They never use a real provider or a real key; end-to-end tests run the `harness-testkit` scenarios with the fixed test key.
- The product name, window title, app-data folder name and bundle identifier appear only in `package.json` and `electron-builder.yml` (ADR 0003).
